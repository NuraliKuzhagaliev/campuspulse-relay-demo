# Public illustrative deployment

The public demo uses the existing React frontend and FastAPI Python gateway in one service, with relative `/api` calls. It does not require a local server or expose the separate MCP server. This deployment remains separate from the mandatory GCP/Vertex AI Agent Engine acceptance gate.

The selected hosting path is a Render **free** Docker web service, in the owner-confirmed workspace. No paid database, disk, worker, upgrade, model service or GCP resource is requested. The service configuration is created directly through Render MCP using `infra/Dockerfile.public`; no Blueprint manages it. Automatic deploys are disabled so documentation/evidence commits do not reset visitor workspaces or spend build quota.

The runtime installs `requirements.public.lock.txt`, which excludes Google Cloud, ADK and Gemini packages. Public mode refuses managed-agent/Google OAuth configuration at startup. Google routes, judge invitation administration, scheduler/internal operations, MCP, OpenAPI and test routes are blocked. Calendar approval/read-back operates exclusively on the explicitly illustrative local adapter. The assistant remains disconnected and cannot fabricate AI answers.

Each anonymous visitor receives an independent 256-bit capability cookie with Secure, HttpOnly and SameSite=Strict protection. API reads and writes use its tenant only. Mutations additionally require the workspace's CSRF value and a valid origin. A new browser context receives a different workspace; source IDs cannot authorize cross-workspace access. The fresh-demo control invalidates the prior capability and deletes that workspace's stored records. Temporary sessions expire after two hours, and expired records are periodically removed. A restart, redeploy or idle spin-down can reset everything sooner. The UI discloses this in EN/RU/Kazakh and avoids persistent browser copies of public workspace snapshots.

Public imports support text PDFs, Markdown, TXT and normalized ICS up to **2 MiB**, with at most 12 sources including the examples and at most 100 imported/simulated Calendar events. Global/session request limits, a workspace cap and two concurrent mutations bound the demo. These limits are intended for small demonstration use, not production availability. No sensitive personal coursework is needed for verification.

Manual GitHub refresh reads the dedicated public repository from the backend. Identical public source observations may be reused for five minutes across visitor workspaces to respect GitHub's shared unauthenticated quota. The original commit, bytes and fetch timestamp are retained. Cache expiry triggers a real read; unavailable/quota-limited reads return useful typed errors instead of fabricated success. Durable autonomous polling remains part of the pending GCP deployment.

Render's free service sleeps after 15 minutes without traffic and can take about a minute to wake. Its filesystem is temporary and resets on spin-down, restart and redeploy. Free quotas are shared with the owner's other services. No card or paid upgrade is added for this deployment. See [Render free-service documentation](https://render.com/docs/free). Actual service ID, URL, commit, deployment status and browser results are recorded only after observation in `docs/evidence/public-deployment.json` and `release/manifest.json`.

To reproduce the public mode locally on the prepared D: machine, create `.local/public-venv` with the existing Python runtime, install `requirements.public.lock.txt`, build the frontend, then run `scripts/run-public-demo.ps1`. This launcher removes live-connection configuration only in its child process and stores all local state on D:. Production uses the Docker image's temporary Linux filesystem managed by the hosting provider.
