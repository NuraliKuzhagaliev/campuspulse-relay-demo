# Known limitations — release candidate

- A complete public illustrative frontend/Python demo is verified on Render, separate from the mandatory GCP gate. Cloud resource identity, remote API, actual model/tool loop and cloud MCP token renewal/restart remain unverified.
- The dedicated Calendar exists, but the application has no live Calendar consent/shared identity yet. All current apply/read-back receipts use a clearly labeled illustrative local adapter. No personal-calendar events were changed.
- OAuth external-browser pairing, encrypted credential storage, verified calendar selection, Firestore and authenticated Scheduler are implemented but require live integration testing. Judge isolation is implemented with one-use invitations, exclusive calendar leases, expiry and reserved request capacity; hosted Calendar access is unverified. A separate explicitly approved empty calendar is required per visitor, and is never automatically reassigned.
- Text extraction is conservative, designed for explicit assignment sections, ISO timestamps with offsets, effort fields and checklist rubrics. General natural-language extraction is not implemented as a standalone local NLP model. Unknown/ambiguous dates remain null. Scanned OCR is not configured. No learning or grade prediction is made.
- Local change radar has a real controlled repository edit proof. Hosted autonomy and real Calendar incremental sync are unverified; 410/pagination behavior is covered with deterministic connector tests.
- Undo preserves edited/unrelated events. It removes unchanged events created by the selected receipt; deleted prior blocks require a fresh preview to restore, because old approvals cannot safely recreate them.
- EN/RU/Kazakh operational UI is translated and tested locally and on the actual hosted URL, including public session/reset/limit notices. Course titles, quotations, exact event titles, identifiers and original diagnostics intentionally remain verbatim. This is not general document translation; real multilingual Gemini responses remain unverified.
- The Windows release is unsigned. Installation and smoke status are recorded in the manifest/evidence; do not claim code signing or recommend bypassing SmartScreen. The preserved Windows release remains verified with its local gateway. Public browser verification does not establish hosted desktop OAuth or managed-agent acceptance.
- Automated installed regression still uses an instrumented picker and checks notification dispatch only. The separate unmodified picker import and actual bottom-right notification visibility passed with human interaction; details are in desktop-native-result.json. The Windows helper failed twice at kernel asset initialization (os error 3). Visibility was explicitly user-confirmed, while click/focus behavior remains unverified. Google authentication remains pending.
- The user-reported original import error lacked rejected-request metadata. The exact diagnostic was reproduced before upload on the renderer file-input multipart route and corrected without opening that route in IPC. Both corrected desktop import paths/read-back/refresh/cache pass installed regression. The real unmodified picker recheck also passed upload, refresh, snapshot and exact-content read-back in the same profile. The user confirmed actual bottom-right notification visibility; click/focus behavior remains unverified. New trace logs redact dynamic path segments, query values and payloads.
- Automated AA checks cover three primary states and explicit viewport/keyboard checks, not a complete accessibility certification. No assertion of defect-free behavior is made.
- The presentation PDF uses rendered slide pages because the bundled native PDF exporter lacks standard-font data. Its PPTX retains editable native text and shapes.
- No interviews, grade/stress improvements, calibrated success probabilities, p95 from one observation, award guarantee or world-first claim is supported.

- Unauthenticated GitHub API quota was reached during final verification; the final recheck passed after its reported reset. Typed rate-limit errors/backoff preserve prior observations. Public polling now defaults to 300 seconds; authenticated polling may use 60 seconds. The measured 19.62-second historical proof used a 60-second controlled test.

- Public hosting uses temporary SQLite and two-hour isolated sessions, with earlier resets on idle spin-down/restarts/redeploys. Free compute can need about a minute to wake after 15 minutes idle and is subject to shared quotas. Actual idle reset timing was not measured. Public limits are 2 MiB and 12 sources including examples. Manual public GitHub observations may be reused for five minutes with original commit/fetch time. No persistent datastore or paid upgrade is attached.
